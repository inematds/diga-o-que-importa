Say What Matters

Even the smartest agent in the world still can’t read your mind. People who communicate better get more from it.

See the 6 ideasView on GitHub
In a nutshell

This is a free guide to working well with AI agents, the assistants that write, code, and organize tasks for you. The main idea is simple: an agent doesn’t know what you want until you tell it, and people who communicate better get better results. Here you’ll find six practical ideas, a ready-to-use script for having the agent interview you before it starts, a project dictionary template, and a checklist. It’s for people who code and people who don’t. Just read it and apply it to your next request.

The thesis

The bottleneck isn’t the model. It’s the conversation.

Models improve every month, but the gap between what you think and what you say remains. That’s where the agent makes things up.

🗣️ Communication is the skill

People who write clearly, explain why, and describe what went wrong get much better results.

🏠 The environment matters

An agent in a messy project produces a mess. An agent in a well-maintained project produces good work.

🪜 Trust is built

Start with the brakes: watch what it does, give it tasks that are easy to check, and only then let it do more.

6 ideas

Six ideas to help the agent deliver what you wanted

Each idea explains why it matters, includes an illustration, and gives you something to do today.

01 · THE BARRIER

The agent can’t read your mind

There’s a communication barrier between you and the agent. No matter how smart the model is, it doesn’t know what matters to you, what your rules are, or why you want something.

If you don’t say it, the agent fills in the blanks. Sometimes it gets it right. Often it makes things up. And since you didn’t mention it, the agent assumes it wasn’t important.

Try it today: In your next request, write one line about what matters and another about why. Example: "It needs to be fast on mobile because my customers use 4G."

02 · THE ENVIRONMENT

Messy workspace, messy work

The agent works inside your project. If the project is a mess that nobody maintains, garbage goes in and garbage comes out. If it’s organized, with tests and checks, the agent gets more things right.

Think of it this way: if you had a hundred people working for you, how would you help the least capable one do good work? Clear rules, tests that catch mistakes, and a tidy workspace. That raises the baseline. The same goes for an agent.

Try it today: Choose one thing to tidy up in your project: an instruction file for the agent, a test that catches the most common mistake, or an organized folder.

03 · THE INTERVIEW

Let the agent interview you

The biggest danger is what you don’t even know you don’t know: security, how the system will go live, who will use it, and what happens when something goes wrong. If you don’t say, the agent decides for you.

The solution is to turn the conversation around. Before building anything, ask the agent to interview you, one question at a time, until there are no questions left. You get everything out of your head, and the agent stops guessing. The ready-to-use script is in the toolkit below.

Try it today: Paste the interview script from the toolkit before your next project and answer every question, even the ones that seem obvious.

04 · ONE SHARED LANGUAGE

The same word everywhere

If the customer says "order," you say "order," the agent writes "order" in the code, and the screen shows "order," everyone means the same thing. When everyone uses a different name (order, request, purchase, sale), confusion follows.

Create a small project dictionary: each term, what it means, and what it is NOT. Give it to the agent and update it whenever a new word comes up. Clear thinking leads to a clear product.

Try it today: Write down the five most important words in your project, with one sentence for each. Use the toolkit template.

05 · A SOLID FOUNDATION

A huge document won’t save a bad project

Some people try to replace code with a huge specification and end up taking care of the document alone. What often happens is that the code slowly gets worse, and the agent gets worse along with it, because it works inside the code, not the document.

A good project lets you change one thing without breaking another. It also helps a lot when the agent can open the system, click around, take a screenshot, and see the result for itself instead of imagining it.

Try it today: Ask the agent: "What makes changes difficult in this project?" Then fix the first item on the list.

06 · THE LADDER

Brakes first, accelerator later

When you learn to drive, the first pedal is the brake. It’s the same with an agent: don’t trust it blindly just because something worked once. Being cautious is good.

Start by watching everything it does. Give it boring tasks that are easy to check: draft replies, organize lists, review text. As trust grows, move up a step: two agents at once, custom skills, connections to email and calendar.

Try it today: List three boring tasks from your week that you can check in two minutes. Start with those.

Bonus

Higher baseline, less effort

When the environment is good and tests catch what slips through, you don’t need to turn the model’s effort all the way up. Medium effort gets the job done, costs less, and responds faster. Before chasing the newest model, improve the place where the agent works: that’s where the biggest gain is.

Toolkit

Copy and use

Two ready-to-paste texts for your agent and a ladder to see where you are.

Script: the agent interviews you

Paste this before asking for anything new. It works with any agent.

Before you start, interview me about what I want to build.
Ask ONE question at a time and wait for my answer.
Ask about: who it is for, what it needs to do, what must NOT happen,
security and data, how it will go live, and how we’ll know it’s good.
If I don’t know, give me the options with their pros and cons and recommend one.
Stop only when there are no questions left. At the end, summarize everything in bullet points
and ask me to confirm before writing anything.

Template: project dictionary

Save this in a project file (for example, DICTIONARY.md) and ask the agent to follow it.

# Project dictionary
Always use these words in the code, on the screen, and in conversation.

## Order
What it is: a purchase the customer confirmed, with items and an address.
What it is NOT: a cart (not confirmed yet).

## Customer
What it is: the person who buys.
What it is NOT: the person who uses the dashboard (that’s a "support agent").

The opportunity

Where the opportunity lies

Programming was the first kind of work to change because code is easy to check. Everyday work is harder: every business does things differently. That’s why the big opportunity is to take work processes, turn them into steps an agent can follow, and bring that to businesses. People who communicate well get there first.

Checklist

Before your next request

Six quick questions. If the answer is no, you already know what to do.

  • Did I say what matters and why?
  • Is the project organized enough for the agent to work well?
  • Did I let the agent interview me before it started?
  • Does everyone use the same words for the same things?
  • Can the agent see the result working?
  • Am I on the right step of the trust ladder?

Models will improve. But they will never read your mind.
